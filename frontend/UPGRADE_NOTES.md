# CareBridge AI upgrade, round 3: landing hero, shared components, alerts, forecast dashboard, AI form helper, language and voice

## What was added or changed
**Landing page.** New two-column hero: the headline "Every Donation. A Real Difference.", your supporting text, **Donate Now** and **Explore Community Needs**, and a trust line that appears only when the backend reports verified organizations. The old AI-generated hero image (with its doodle overlays) and the full-bleed photo background were removed. The right column shows the licensed photo when `public/images/hero/hero.json` exists; until then it shows **live open needs** from the backend (or an honest empty state), never a stand-in picture. No impact numbers are hard-coded.
**Hero image: exact paths and licence.** Asset folder `frontend/public/images/hero/` (`hero-1600.jpg/.webp`, `hero-800.jpg/.webp`, `hero.json`). **No photograph is included, so there is no source or licence to report yet.** I could not download a licensed photo (no network) and an AI-generated image would break your own rules. Add yours with `python scripts\make_hero_assets.py photo.jpg --alt "..." --license "..." --credit "..." --source-url ...` (crops 4:3, optimizes, strips GPS/camera metadata, requires a description and a licence statement; the page shows the credit and licence under the photo). See `public/images/hero/README.md`.
**Design system.** `PageHeader` and `StatCard` are now flat and compact on every page (the gradient banners are gone). One `StatusBadge` for every status (pending amber, approved/delivered green, rejected/failed red, in progress blue, cancelled grey, unknown values neutral). Shared skeleton, empty and error states. Compact sidebar with collapsible groups.
**Reusable table.** `components/DataTable.jsx`: search, filters, column sorting, pagination, loading skeleton, empty and error states with retry, row actions, an accessible details drawer, and one card per record on small screens. Applied to **Donations** and **Needs** (the other 14 tables still use their own markup). Links such as `/needs?open=4` open that record.
**Admin alerts** (`GET /admin/alerts`, shown on the admin dashboard): needs open 14+ days, organizations awaiting verification, unreviewed anomaly flags, donations not delivered after 14 days. Each is a count calculated from stored records, with links to the records. Deliveries "past their expected date" and "failed workflows" are **not calculated**, because donations store no expected date and no failure log exists; the panel says so.
**Demand forecast dashboard** (`/admin/forecast`, `GET /admin/forecast-dashboard`): real history, forecast, method and backtest error against a naive baseline, and shortfall risk. The forecaster returned no prediction interval, so the range shown is **empirical** (the 80th percentile of that method's past one-step errors) and appears only with at least 5 past forecasts; otherwise the page says no range is available. Shortfall risk is the existing documented rule (expected units vs stock and interested donors), stated on the page as a rule, not a probability.
**AI help in the need form** (`POST /need-assist`): suggestions for category, urgency, title, description and missing information, shown in a separate panel; nothing reaches the form until the person presses "Use". With a model: validated JSON only; without one, keyword rules, labelled as such. Rate limited; admins and organizations only. Description and title fields added to the form (the backend already accepted them).
**Assistant: language and voice.** A reply-language selector (18 languages, fixed list; the choice is remembered for the session) and a microphone button using the browser's speech recognition, with clear messages for denied permission, no microphone, unsupported browser or language. Typing always works; nothing is sent until you press Send.
**Donations API:** status, delivered/confirmed dates and delivery note are now returned (additive).
**New or changed endpoints:** `GET /admin/alerts`, `GET /admin/forecast-dashboard`, `POST /need-assist`, `POST /chat/stream` gained an optional `language`, `GET /donations/` gained fields. **No new migration and no new environment variable in this round** (the earlier `20261022_chat` and `20261023_llm` migrations are still required: run `alembic upgrade head`).

## Windows PowerShell
```powershell
cd backend ; .\.venv\Scripts\Activate.ps1 ; pip install -r requirements.txt ; alembic upgrade head ; python -m uvicorn app.main:app --reload
cd ..\frontend ; npm install ; npm run dev            # http://localhost:5173
```
Keep your own `backend\.env` (the ZIP has none). Optional photo: see above. Optional model for chat and the form helper: `LLM_API_KEY` or `LLM_BASE_URL` in `.env`.
